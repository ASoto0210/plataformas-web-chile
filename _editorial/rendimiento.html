Una tienda rápida debe permitir terminar la tarea.

Medir el tiempo de carga ayuda, pero no sustituye buscar un producto, entender sus variantes y completar una compra. Un sitio puede obtener una buena puntuación y conservar un formulario difícil de usar.

Nuestra propuesta es observar primero el recorrido real en móvil y después usar mediciones técnicas para localizar el problema.

Tres señales distintas

Google utiliza Core Web Vitals para carga, respuesta a interacciones y estabilidad visual. Sus referencias de buena experiencia son:

  • LCP: hasta 2,5 segundos para el elemento de contenido principal.
  • INP: hasta 200 milisegundos para la respuesta a interacciones.
  • CLS: hasta 0,1 para desplazamientos de diseño.

La evaluación utiliza el percentil 75 de las visitas y distingue móvil y escritorio. No mezcles el resultado de una simulación de laboratorio con datos observados de usuarios reales.

Repite un recorrido representativo

  1. Escoge una página de entrada, una categoría, un producto y el carrito.
  2. Prueba con un teléfono y una conexión habituales para tu público.
  3. Registra imágenes que tardan, saltos de contenido, controles sin respuesta y campos que impiden avanzar.
  4. Compara con mediciones repetidas, indicando herramienta, fecha, condiciones y URL.
  5. Corrige primero un problema relevante y vuelve a medir con el mismo método.

Incluye accesibilidad

WCAG 2.2 ofrece criterios verificables para interfaces accesibles. Revisa teclado, foco, etiquetas, contraste y mensajes de error. Una auditoría automática ayuda a detectar algunos problemas, pero no prueba por sí sola conformidad.

No prometas un aumento de ventas por bajar una métrica. Relaciona la mejora con la tarea del comprador y, cuando haya suficiente evidencia, observa el resultado comercial en su contexto.
